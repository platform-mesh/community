## Working Agreement

### Communication
- **Zulip** is the primary communication channel [link](https://linuxfoundation.zulipchat.com/#narrow/channel/532985-neonephos-platform-mesh-discussion/topic/wg-modularization/with/617890560).
- **GitHub** (Issues, PRs) is used for everything beyond direct communication.
- Raise blockers **as early as possible** to avoid heading in the wrong direction

### Meetings
- **1 weekly meeting, no dailies.**
- Ad-hoc meetings may be called with only the relevant parties when needed.

### Decisions
- Decision logs are published. Significant decisions are documented in **ADRs / RFCs**.


### Code Reviews & Pull Requests
- Code feedback goes in the **PR**, not in side channels.
- PRs must include the **"why"**, not just the "what".
- Use human PR descriptions, not full AI-generated text.


### Scope
- **In scope:** A clear way of working is established and work to be done is clear (Epics, tasks ...)
- **Out of scope:** 100% implementation done for the work defined. Implementation follows the current open source working model.
